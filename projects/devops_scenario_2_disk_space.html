💾 Scenario 2: Server Running Out of Disk Space

📢 The Alert: "Your server disk is 95% full! Running out of space!"

⏱️ Your Time: Find problem → Free space → Verify (5-10 minutes)

🎯 Your Goal: Get disk usage back to healthy (< 80%)

🚀 The Problem Explained

What happens when disk fills up:
  • Applications can't write data
  • Databases crash
  • Logs stop being created
  • Services fail
  • Website goes down

📊 Your Approach

Check Disk
→
Find Culprit
→
Drill Down
→
Delete Old Files
→
Verify ✅

🚀 Step-by-Step Walkthrough

STEP 1: Connect to Server

You get the alert and SSH in immediately:

Server: 192.168.1.100 Login: myuser Password: ****
myuser@webserver:~$

What you're thinking: "Disk is full. I need to see what's taking space."

STEP 2: Check Overall Disk Usage

Command:

df -h

Output:

Filesystem Size Used Avail Use% Mounted on /dev/sda1 100G 95G 5G 95% / /dev/sdb1 200G 180G 20G 90% /data tmpfs 8G 0 8G 0% /dev/shm
⚠️ CRITICAL INFO:

• /dev/sda1 = 95% full (only 5G left!) ❌
• /dev/sdb1 = 90% full (20G left)
• Problem: Main disk (/) is almost out of space!

What you're thinking: "Root partition is critical. I need to find what's eating 95GB."

STEP 3: Find Largest Directories

Command:

du -sh /* | sort -hr

Breaking it down:

  • du = disk usage
  • -s = summary (total only)
  • -h = human readable (GB, MB)
  • /* = check all top-level directories
  • sort -hr = sort largest to smallest

Output:

89G /var 4G /usr 2G /home 1G /opt 800M /tmp 100M /root 100M /etc 50M /bin
⚠️ FOUND THE CULPRIT!

• /var = 89GB (almost all the space!)
• Everything else is tiny
• Problem identified: /var is the problem

What you're thinking: "/var contains logs, databases, temp data. Something in there is huge. Probably logs."

STEP 4: Check What's Inside /var

Command:

du -sh /var/* | sort -hr

Output:

85G /var/log 2G /var/lib 1G /var/cache 200M /var/spool 100M /var/www
⚠️ CONFIRMED!

• /var/log = 85GB (logs!)
• This is definitely the problem
• Old log files are piling up

What you're thinking: "Logs are filling up the disk. Let me see which log files are biggest."

STEP 5: Check Individual Log Files

Command:

du -sh /var/log/* | sort -hr

Output:

40G /var/log/syslog 20G /var/log/nginx 15G /var/log/mysql 8G /var/log/apache2 2G /var/log/auth.log
⚠️ BREAKDOWN:

• syslog = 40GB (system logs)
• nginx = 20GB (web server logs)
• mysql = 15GB (database logs)
• apache2 = 8GB (old web server)
• auth.log = 2G (login logs)
Total = 85GB of logs!

What you're thinking: "These are OLD logs. They should be deleted or compressed. Let me check how old they are."

STEP 6: Check Age of Syslog Files

Command:

ls -lh /var/log/syslog*

Output:

-rw-r--r-- 1 root root 40G Aug 01 2026 /var/log/syslog -rw-r--r-- 1 root root 30G Jul 15 2026 /var/log/syslog.1 -rw-r--r-- 1 root root 25G Jul 01 2026 /var/log/syslog.2 -rw-r--r-- 1 root root 20G Jun 15 2026 /var/log/syslog.3
⚠️ ANCIENT FILES!

• syslog (current) = 40GB from Aug 1
• syslog.1 = 30GB from Jul 15
• syslog.2 = 25GB from Jul 1
• syslog.3 = 20GB from Jun 15
Total: 115GB of logs spanning 2+ months!

What you're thinking: "These are months old. I can safely delete the old rotated ones (.1, .2, .3). But let me first check if anything is still reading them."

STEP 7: Check If Services Are Using These Files

Command:

lsof | grep /var/log/syslog

Output:

rsyslogd 1234 root 5w REG 8,1 40G Aug 1 15:30 /var/log/syslog
⚠️ IMPORTANT!

• rsyslogd = System logging daemon
• Only the current /var/log/syslog is open
• Old rotated files (.1, .2, .3) are NOT open
• Safe to delete: syslog.1, syslog.2, syslog.3

What you're thinking: "Perfect! Only rsyslogd is using the current syslog. The old ones aren't being read. I can delete them safely."

STEP 8: Delete Old Syslog Files (Free Space!)

Command:

rm /var/log/syslog.1 /var/log/syslog.2 /var/log/syslog.3

Output:

(no output = success!)
✅ OLD LOGS DELETED!

• Deleted: syslog.1 (30GB), syslog.2 (25GB), syslog.3 (20GB)
• Freed: 75GB
• Current syslog (40GB) still intact

What you're thinking: "Excellent! 75GB freed. Let me also clean nginx old logs."

STEP 9: Check Nginx Log Files

Command:

ls -lh /var/log/nginx/

Output:

-rw-r--r-- 1 nginx nginx 15G Aug 20 2026 access.log -rw-r--r-- 1 nginx nginx 3G Aug 20 2026 error.log -rw-r--r-- 1 nginx nginx 2G Aug 10 2026 access.log.1 -rw-r--r-- 1 nginx nginx 500M Aug 10 2026 error.log.1

Decision:

  • ✅ Keep: access.log, error.log (current logs, nginx writing to them)
  • ❌ Delete: access.log.1, error.log.1 (old rotated logs, not in use)

Command:

rm /var/log/nginx/access.log.1 /var/log/nginx/error.log.1
✅ NGINX LOGS CLEANED

• Freed: 2.5GB more
STEP 10: Verify Disk Space Freed

Command:

df -h

Output:

Filesystem Size Used Avail Use% Mounted on /dev/sda1 100G 20G 80G 20% / /dev/sdb1 200G 180G 20G 90% /data tmpfs 8G 0 8G 0% /dev/shm
✅ MASSIVE IMPROVEMENT!

• Was: 95% (5G available)
• Now: 20% (80G available)
• Freed: 75GB total
• Disk is now healthy!

What you're thinking: "Perfect! Back to normal. Now let me verify services are still running."

STEP 11: Verify Services Still Running

Command:

systemctl status nginx

Output:

● nginx.service - A high performance web server Loaded: loaded (/etc/systemd/system/multi-user.target.wants/nginx.service; enabled) Active: active (running) Main PID: 5678
✅ NGINX RUNNING - No issues

Check MySQL:

● mysql.service - MySQL Database Server Loaded: loaded Active: active (running)

• No data loss

🎓 Key Commands You Learned

df (Disk Free)

df -h

Shows total disk usage per filesystem. -h = human readable (GB/MB).

du (Disk Usage)

du -sh /var

Shows what's taking space. -s = summary, -h = human readable.

ls (List Files with Size)

ls -lh /var/log/

Shows file details including size and date. -h = human readable.

lsof (List Open Files)

lsof | grep syslog

Shows which processes have files open. Use before deleting!

rm (Remove Files)

rm /var/log/syslog.1

Delete files. BE CAREFUL - files are gone forever!

⚠️ Common Issues & Solutions

❌ Problem: "Permission denied" when deleting

rm /var/log/syslog.1 -bash: /var/log/syslog.1: Permission denied

Why: Log files are owned by root. You need sudo.

Solution:

sudo rm /var/log/syslog.1

❌ Problem: du command is slow

Why: Scanning large filesystems takes time.

Solution: Use --max-depth to limit recursion:

du -sh /var --max-depth=1

❌ Problem: Deleted file but disk didn't free up

Why: File is still open by a process (handles not closed).

Solution: Restart the service using the file:

sudo systemctl restart nginx

❌ Problem: Accidentally deleted current log file

Why: Oops! You deleted a file that's still in use.

Solution: Service will recreate it on next write. To speed up:

sudo systemctl restart nginx

No data loss - just lost logs from that moment.
