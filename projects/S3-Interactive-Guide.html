AWS S3 Explained

Simple Storage Service — Interactive Learning Guide

📦 What is S3?

S3 = Simple Storage Service — AWS's object-based storage for any type of files. It's serverless, scalable, and incredibly reliable.

Global Service

Exists across all AWS regions worldwide

Unlimited Storage

Store as many objects as you need

Object-Based

Not a file system — store files as objects

Serverless

No infrastructure to manage or maintain

What Can S3 Do?

✅ Yes, S3 Can:

✓ Store any type of files

✓ Download, upload & access files

✓ Host static websites

✓ Backup & disaster recovery

❌ No, S3 Cannot:

✗ Execute files or run code

✗ Install operating systems

✗ Install databases

✗ Act as a web server

🎁 Buckets & Objects

S3 organizes storage using two key concepts: Buckets (containers) and Objects (files).

What is a Bucket?

A bucket is a container where you store your objects (files). Think of it like a folder, but with important differences:

Regional

Created in a specific AWS region

Globally Unique Names

Bucket names must be unique across all AWS accounts

No Nesting

Cannot create buckets inside buckets

Private by Default

Only accessible to the bucket owner

What is an Object?

An object is a file stored in S3. Every object has:

  • KEY — The object's name/identifier (e.g., "photos/puppy.jpg")
  • VALUE — The actual file data
  • Metadata — Information about the object (size, type, etc.)

URL Structure

Every object has a unique URL you can use to access it:

https://bucket-name.s3.region.amazonaws.com/object-key

Example:
https://my-photos.s3.ap-south-1.amazonaws.com/photos/puppy.jpg

🔄 Versioning

Versioning lets you keep multiple versions of an object — like a backup system. Once enabled, it can't be disabled, but it can be suspended.

How Versioning Works

When versioning is enabled:

  • Every change creates a new version
  • Each version gets a unique Version ID
  • You can retrieve any previous version
  • Acts as a backup & recovery tool

Important Version Operations

Delete Marker

When you delete an object, a Delete Marker is applied to the latest version, not old versions.

⚠️ You cannot download a Delete Marker

Restore Object

Simply delete the Delete Marker and the object is restored automatically.

✓ Easy one-click restore

💡 Pro Tip: Versioning can be suspended but never disabled. When suspended, future uploads still create versions, but updates don't.

Storage Limits

How to Upload Files

Single PUT (Simple Upload)

Use when: Uploading files smaller than 5GB

Where: AWS Console, API, CLI

Max file size: 5GB

Multi-Part Upload (MPU)

Use when: Uploading files larger than 100MB

Where: AWS CLI only (not Console)

Faster parallel uploads ⚡

🚀 Multi-Part Upload (MPU): Breaks your file into chunks, then uploads each chunk separately and simultaneously. Recommended for any file larger than 100MB for faster transfers.

📝 WORM Model

S3 follows the WORM principle (Write Once, Read Many):

Write Once

After you upload an object, it's immutable (unless versioning is on)

Read Many

You can download and read the object as many times as needed

Consistency

Guaranteed data consistency after upload

Reliability

Data is stored redundantly across multiple locations

🔐 Security & Access

Default Behavior

Buckets are PRIVATE by default. Only the bucket owner can access objects unless explicit permissions are granted.

Making Buckets Public

You can make a bucket or specific objects public, but only if business requirements demand it:

  • Bucket Policies — Control who can access what
  • IAM Permissions — Identity and Access Management
  • Access Control Lists (ACL) — Legacy permission system

⚠️ Making buckets public creates security risks. Only do this when necessary and use proper access controls.
