🖥️ What is EC2?

EC2 = Elastic Compute Cloud — Virtual computers (servers) that you can launch on-demand in AWS. You control the OS, applications, and configurations.

Virtual Servers

Launch computers in minutes instead of days

Elastic (Scalable)

Increase or decrease computing capacity on demand

Pay-As-You-Go

Only pay for the capacity you actually use

Full Control

Root/administrator access to your instances

💾 Instance Storage

EC2 instances use different types of storage for different purposes.

Storage Types

EBS (Elastic Block Store)

Persistent block storage that survives instance termination. Used for OS and data.

Instance Store (Ephemeral)

Temporary storage tied to instance hardware. Lost when instance stops/terminates.

EFS (Elastic File System)

Network file system accessible across multiple instances

S3 Integration

Access object storage for backups, data, and media files

💡 Best Practice: Use EBS volumes for data you want to keep, and configure snapshots for backup and disaster recovery.

🔐 Security & Networking

Security Groups

Act as virtual firewalls that control inbound and outbound traffic to your instances.

Inbound Rules: Control who can connect TO your instance
Outbound Rules: Control what your instance can connect TO

Key Pairs

Used for SSH access to Linux/Unix instances or RDP access to Windows instances.

  • Private Key: Kept securely on your local machine
  • Public Key: Installed on the EC2 instance
  • Never share or lose your private key

IAM Roles

Attach IAM roles to instances to give them permissions to access other AWS services securely.

🔧 Troubleshooting Guide

Cannot Connect to Instance (SSH/RDP Fails)

Step 1: Verify Instance is Running

  • Check instance state is "running" in AWS Console
  • Check that status checks show "2/2 checks passed"
  • Wait 2-3 minutes for the instance to fully initialize

Step 2: Verify Security Group Rules

  • Check Security Group allows inbound SSH (port 22) or RDP (port 3389)
  • Your source IP should be in the allowed range (use 0.0.0.0/0 only for testing)
  • Rule should allow your protocol (TCP for SSH/RDP)

Step 3: Verify Key Pair

  • Ensure you're using the correct private key file
  • Key file permissions must be 400 (chmod 400 on Linux/Mac)
  • Verify key pair was used when launching the instance

Step 4: Verify Network Configuration

  • Instance has a public IP or Elastic IP address
  • Subnet auto-assigns public IPs (or assign manually)
  • Internet Gateway is attached to VPC
  • Route table has route to Internet Gateway

High CPU or Memory Usage

Step 1: Monitor with CloudWatch

  • Check CloudWatch metrics for CPU, network, disk I/O
  • Identify if usage spike is normal or abnormal
  • Check for runaway processes

Step 2: SSH Into Instance

  • Use top or htop to see CPU/memory hogs
  • Check application logs for errors
  • Identify which process is consuming resources

Step 3: Take Action

  • Kill the offending process if it's unwanted
  • Restart the service/application
  • Scale up to a larger instance type if legitimate traffic
  • Add load balancer to distribute traffic

Instance Won't Start

Common Causes & Solutions:

  • Insufficient capacity: Try different AZ or instance type
  • Account limits: Request limit increase from AWS Support
  • Subnet full: Use different subnet or VPC
  • AMI deleted: Use different AMI or restore from snapshot
