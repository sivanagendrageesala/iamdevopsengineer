⭐ PART 1: Setup AWS EC2 Instance (5 minutes)

Step 1: Go to AWS Console

1. Open your browser and go to:

https://console.aws.amazon.com/

2. Sign in with your AWS account

3. Search for "EC2" in the search bar at the top

AWS Console → Services → EC2

What you'll see: EC2 Dashboard with instance options

Step 2: Launch New Instance

Click: "Launch instances" (big orange button)

Choose AMI (Amazon Machine Image):

Option Details Free Tier
Ubuntu 20.04 LTS Latest, most popular for DevOps ✅ Free
Amazon Linux 2 AWS-native, CentOS-based ✅ Free

👉 SELECT: Ubuntu 20.04 LTS (x86)

Step 3: Instance Type

Select: t2.micro (Free Tier eligible)

t2.micro - 1 GB RAM, 1 CPU (More than enough for practice)

Click: "Next: Configure Instance Details"

Step 4: Configure Security Group

Skip to "Step 6: Configure Security Group"

Add these inbound rules:

Type Protocol Port Source Why
SSH TCP 22 0.0.0.0/0 (Anywhere) Connect from PuTTY
HTTP TCP 80 0.0.0.0/0 Web server traffic
HTTPS TCP 443 0.0.0.0/0 Secure web traffic
MySQL TCP 3306 0.0.0.0/0 Database access
⚠️ WARNING: Setting source to 0.0.0.0/0 is NOT secure for production! Only use on free tier practice instances.
Step 5: Create Key Pair

When prompted for key pair:

1. Click: "Create new key pair"

2. Name: devops-practice

3. Format: .pem

4. Click: "Create key pair"

✅ File "devops-practice.pem" will download
✅ SAVE THIS FILE - you'll need it to connect!
✅ Never share this file!
Step 6: Launch & Wait

Click: "Launch instances"

Wait for:

Instance State: Running (green) Status Checks: 2/2 passed (green)

Note: This takes 2-3 minutes

✅ Instance is running
✅ Ready to connect!

🔌 PART 2: Connect via SSH from PuTTY (2 minutes)

Step 1: Get Instance Details

In AWS Console, find your instance and note:

Detail Where to Find Example
Public IP Instances list (last column) 54.123.45.67
Instance ID Instances list i-0abc123def456

Copy the Public IP address

Step 2: Convert PEM to PPK (For PuTTY)

PuTTY needs PPK format, not PEM. Here's how to convert:

Option A: Use PuTTYgen (Graphical)

  1. Download: PuTTYgen (puttygen.exe)
  2. Open PuTTYgen
  3. Click: "Load" → Select devops-practice.pem
  4. Click: "Save private key" → Name: devops-practice.ppk

Option B: Use Command Line (Easier)

puttygen devops-practice.pem -O private -o devops-practice.ppk
✅ You now have devops-practice.ppk
✅ Ready to use in PuTTY!
Step 3: Open PuTTY and Connect

1. Open PuTTY

2. In "Host Name":

ubuntu@54.123.45.67

(Replace 54.123.45.67 with your Public IP)

3. Go to: Connection → SSH → Auth

4. Click: "Browse" → Select devops-practice.ppk

5. Click: "Open"

6. Accept warning about server key (click "Yes")

Welcome to Ubuntu 20.04.1 LTS ubuntu@ip-172-31-0-123:~$
✅ Connected to your EC2 instance!
✅ Ready to install services!

📦 PART 3: Install Services (10 minutes)

Copy-paste these commands one at a time in your PuTTY terminal:

Update System
sudo apt update && sudo apt upgrade -y

What it does: Updates package lists and system packages

Wait time: 2-3 minutes

Install Nginx (Web Server)
sudo apt install -y nginx

Start it:

sudo systemctl start nginx sudo systemctl enable nginx

Verify:

sudo systemctl status nginx

Expected output:

● nginx.service - A high performance web server Active: active (running)
Install MySQL (Database)
sudo apt install -y mysql-server

Start it:

sudo systemctl start mysql sudo systemctl enable mysql

Verify:

sudo systemctl status mysql
Install Basic Tools
sudo apt install -y curl wget htop net-tools

These are helpful for troubleshooting!

✅ All services installed!
✅ Ready to practice scenarios!

🔴 SCENARIO 1: Website Down (Port Conflict) - 15 minutes

The Plan: Stop nginx, start Apache on port 80, then fix it

Step 1: Stop nginx

sudo systemctl stop nginx

Step 2: Install Apache

sudo apt install -y apache2

Step 3: Start Apache on port 80

sudo systemctl start apache2

Step 4: Try to restart nginx (will fail)

sudo systemctl start nginx

Expected error:

Job for nginx.service failed because the control process exited with error code. bind() to 0.0.0.0:80 failed (98: Address already in use)

Step 5: Check what's using port 80

sudo netstat -tuln | grep 80

Output shows:**

tcp 0 0 0.0.0.0:80 0.0.0.0:* LISTEN 1234/apache2

Step 6: Now fix it!

sudo systemctl stop apache2 sudo systemctl disable apache2 sudo systemctl start nginx

Step 7: Verify nginx is running

sudo systemctl status nginx

Step 8: Test it works

curl http://localhost/
✅ SCENARIO 1 COMPLETE!
✅ You diagnosed a port conflict!
✅ You fixed it and verified the fix!

💾 SCENARIO 2: Disk Full (Old Logs) - 15 minutes

The Plan: Fill disk with logs, then clean them up

Step 1: Create fake old log files

sudo dd if=/dev/zero of=/var/log/syslog.1 bs=1M count=100 sudo dd if=/dev/zero of=/var/log/syslog.2 bs=1M count=100 sudo dd if=/dev/zero of=/var/log/nginx/old.log bs=1M count=50

Step 2: Check disk usage

df -h

Step 3: See what's taking space

du -sh /* | sort -hr

Step 4: Find the large files

du -sh /var/log/* | sort -hr

Step 5: Delete old logs

sudo rm /var/log/syslog.1 /var/log/syslog.2 /var/log/nginx/old.log

Step 6: Verify disk freed

df -h
✅ SCENARIO 2 COMPLETE!
✅ You identified disk hogs!
✅ You freed up disk space!

⚡ SCENARIO 3: High CPU/Memory (Slow Queries) - 20 minutes

The Plan: Run a CPU-heavy query, monitor it, kill it

Step 1: Login to MySQL

mysql -u root

Step 2: Create test database

CREATE DATABASE testdb; USE testdb;

Step 3: Create a large table

CREATE TABLE users ( id INT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(255), email VARCHAR(255) ); INSERT INTO users (name, email) VALUES ('test', 'test@test.com'); INSERT INTO users SELECT * FROM users; INSERT INTO users SELECT * FROM users; INSERT INTO users SELECT * FROM users;

Step 4: Exit MySQL and open in another terminal

EXIT;

In PuTTY, open NEW session (Connection → SSH → Tunnels → open new terminal)

Step 5: In first terminal, run slow query

mysql -u root -e "USE testdb; SELECT * FROM users WHERE id > 0;"

Step 6: In second terminal, monitor CPU

top

Press 'q' to exit top

Step 7: Check MySQL processes

mysql -u root -e "SHOW PROCESSLIST;"

Step 8: Kill the query

mysql -u root -e "KILL ;"
✅ SCENARIO 3 COMPLETE!
✅ You monitored CPU usage!
✅ You found and killed slow queries!

🗄️ SCENARIO 4: Database Connection Failed - 20 minutes

The Plan: Break MySQL, then fix it

Step 1: Stop MySQL

sudo systemctl stop mysql

Step 2: Try to connect (will fail)

mysql -u root

Expected error:

ERROR 2002 (HY000): Can't connect to local MySQL server through socket '/var/run/mysqld/mysqld.sock' (2 "No such file or directory")

Step 3: Check MySQL status

sudo systemctl status mysql

Expected:

● mysql.service - MySQL Community Server Active: inactive (dead)

Step 4: Check error log

sudo tail -50 /var/log/mysql/error.log

Step 5: Now fix it!

sudo systemctl start mysql

Step 6: Verify it's running

sudo systemctl status mysql

Step 7: Test connection

mysql -u root -e "SELECT 1;"
✅ SCENARIO 4 COMPLETE!
✅ You diagnosed a downed database!
✅ You restarted and verified it!

💾 SCENARIO 5: Backup Failed - 15 minutes

The Plan: Create backup script, make it fail, then fix it

Step 1: Create backup script

sudo nano /usr/local/bin/backup.sh

Paste this (copy entire block):

#!/bin/bash echo "[$(date)] Starting backup" mysqldump -u backup_user -pWRONG_PASSWORD testdb > /backups/backup.sql 2>&1 if [ $? -eq 0 ]; then echo "[$(date)] Backup SUCCESS" else echo "[$(date)] Backup FAILED" fi

Save (Ctrl+O, Enter, Ctrl+X)

Step 2: Make it executable

sudo chmod +x /usr/local/bin/backup.sh

Step 3: Create backups directory

sudo mkdir -p /backups sudo chmod 777 /backups

Step 4: Run backup (will fail)

sudo /usr/local/bin/backup.sh

Expected: Shows FAILED

Step 5: Create backup user

mysql -u root -e "CREATE USER 'backup_user'@'localhost' IDENTIFIED BY 'backup_password';" mysql -u root -e "GRANT SELECT ON *.* TO 'backup_user'@'localhost';"

Step 6: Update script with correct password

sudo nano /usr/local/bin/backup.sh

Change: -pWRONG_PASSWORD to -pbackup_password

Step 7: Run backup again (will succeed!)

sudo /usr/local/bin/backup.sh

Step 8: Verify backup exists

ls -lh /backups/
✅ SCENARIO 5 COMPLETE!
✅ You created and fixed a backup script!
✅ You verified the backup was created!

🔒 SCENARIO 6: SSL Certificate Expired - 10 minutes

The Plan: Check nginx SSL config

Step 1: Check if SSL is configured

sudo ls -la /etc/nginx/sites-enabled/

Step 2: Check default config

sudo cat /etc/nginx/sites-available/default

Step 3: On AWS, use self-signed cert for practice

sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \ -keyout /etc/ssl/private/nginx-selfsigned.key \ -out /etc/ssl/certs/nginx-selfsigned.crt \ -subj "/C=US/ST=State/L=City/O=Org/CN=localhost"

Step 4: Create HTTPS nginx config

sudo tee /etc/nginx/sites-available/default > /dev/null << 'EOF' server { listen 443 ssl; server_name _; ssl_certificate /etc/ssl/certs/nginx-selfsigned.crt; ssl_certificate_key /etc/ssl/private/nginx-selfsigned.key; location / { root /var/www/html; index index.html; } } server { listen 80; return 301 https://$server_name$request_uri; } EOF

Step 5: Test nginx config

sudo nginx -t

Step 6: Reload nginx

sudo systemctl reload nginx

Step 7: Test HTTPS

curl -k https://localhost/
✅ SCENARIO 6 COMPLETE!
✅ You set up HTTPS!
✅ You understand SSL certificates!

🌐 SCENARIO 7: DNS Resolution Failing - 15 minutes

The Plan: Test DNS resolution locally

Step 1: Test DNS query

nslookup google.com

Expected: Shows IP address

Step 2: Test with Google DNS

dig google.com @8.8.8.8

Step 3: Test local hostname resolution

hostname getent hosts localhost

Step 4: Add custom entry to /etc/hosts

sudo nano /etc/hosts

Add this line:

127.0.0.1 mydevopslab.local

Step 5: Test resolution

ping mydevopslab.local

Expected:

PING mydevopslab.local (127.0.0.1): 56 data bytes 64 bytes from 127.0.0.1: icmp_seq=0 ttl=64 time=0.03 ms
✅ SCENARIO 7 COMPLETE!
✅ You tested DNS resolution!
✅ You added custom DNS entries!
