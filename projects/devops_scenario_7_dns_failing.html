📚 PART 1: Understanding DNS (The Basics)

What is DNS? (Think of it as the Internet's Phone Book)

Real-world analogy:
• You want to call a friend (= you want to visit mysite.com)
• You look up their number in a phone book (= DNS lookup)
• You dial the number (= connect to IP address)
• Friend's phone rings (= server receives request)

In technical terms:

  • DNS = Domain Name System (translates domain names to IP addresses)
  • mysite.com = human-readable domain name
  • 192.168.1.100 = IP address (what DNS translates to)
  • Without DNS = can't connect, website invisible

How DNS Works (Step-by-Step)

🔍 PART 2: Understanding DNS Failure

Common DNS Problems

Problem What Happens Error Message How to Fix
Missing A Record Domain not pointing to server IP NXDOMAIN / Host not found Add A record in DNS provider
Wrong IP Address A record points to wrong IP Connection refused / timeout Update A record with correct IP
Not Propagated DNS change hasn't spread globally Works in some places, not others Wait 5-30 minutes for TTL to expire
Nameserver Down DNS authority server is offline Server not responding Contact DNS provider / switch nameservers
Wrong Nameservers Domain uses wrong DNS authorities SERVFAIL / can't resolve Update nameservers at domain registrar

🚀 PART 3: Step-by-Step Diagnosis & Fix

STEP 1: Test DNS Locally

The Command:

nslookup mysite.com

Scenario A - DNS Works:

Server: 8.8.8.8 Address: 8.8.8.8#53 Non-authoritative answer: Name: mysite.com Address: 192.168.1.100
✅ DNS resolved successfully
✅ mysite.com = 192.168.1.100
✅ Problem is NOT DNS

Scenario B - DNS Fails:

Server: 8.8.8.8 Address: 8.8.8.8#53 ** server can't find mysite.com: NXDOMAIN
⚠️ DNS BROKEN!

• NXDOMAIN = domain doesn't exist in DNS
• A record is missing
• Or domain uses wrong nameservers
Root Cause: DNS Record Missing!

What you're thinking: "DNS can't resolve mysite.com. The domain either doesn't exist in DNS records, or the record is pointing to the wrong IP. Let me check the DNS records."

STEP 2: Check DNS Records at Provider

Log into your DNS provider (Route 53, Cloudflare, GoDaddy, etc)

Look for A Record:

Name Type Value Status
mysite.com A 192.168.1.100 ✅ Correct

If Record is Missing:

⚠️ FOUND THE PROBLEM!

• A record doesn't exist
• Browser can't look up IP address
• Users can't reach website
Solution: Create the A record

What you're thinking: "The A record is missing! I need to create it. The A record should point to my web server's IP address."

STEP 3: Create/Update A Record

In your DNS provider's dashboard:

Field Value Explanation
Name/Host mysite.com The domain name
Type A Points to IPv4 address
Value/Answer 192.168.1.100 Your web server's IP
TTL 3600 How long to cache (seconds)
✅ A record created
✅ Points to correct IP
✅ TTL set to 1 hour

What you're thinking: "Good! I created the A record. Now I need to wait for DNS to propagate. Since I set TTL to 3600 seconds, the change should be everywhere within 1 hour. Let me test it."

STEP 4: Check DNS Propagation

The Command (wait 5-10 minutes first):

dig mysite.com @8.8.8.8

Output (Before Propagation - immediately after creating record):

mysite.com. 0 IN A 192.168.1.100 ;; Query time: 45 msec ;; SERVER: 8.8.8.8#53(8.8.8.8) ;; When: Wed Sep 02 10:35:00 UTC 2026 ;; MSG SIZE rcvd: 45

Output (After Propagation - after 10+ minutes):

mysite.com. 3600 IN A 192.168.1.100 ;; Query time: 12 msec ;; SERVER: 8.8.8.8#53(8.8.8.8) ;; When: Wed Sep 02 10:45:00 UTC 2026 ;; MSG SIZE rcvd: 45

Understanding DNS Propagation:

Metric Meaning What to Expect
TTL: 3600 Time to Live (cache duration) DNS caches for 1 hour
Query time: 12ms How long DNS lookup took Fast = DNS is working
NOERROR Successful response DNS found the record
✅ DNS query successful
✅ A record found
✅ Returning correct IP

What you're thinking: "Perfect! DNS is now resolving correctly. Let me verify the server is actually reachable at that IP address."

STEP 5: Verify Server at That IP

Ping the IP address:

ping 192.168.1.100

Output:

PING 192.168.1.100 (192.168.1.100) 56(84) bytes of data. 64 bytes from 192.168.1.100: icmp_seq=1 ttl=64 time=0.234 ms 64 bytes from 192.168.1.100: icmp_seq=1 ttl=64 time=0.245 ms 64 bytes from 192.168.1.100: icmp_seq=1 ttl=64 time=0.256 ms --- 192.168.1.100 statistics --- 3 packets transmitted, 3 received, 0% packet loss, time 2005ms
✅ Server responds to ping
✅ No packet loss
✅ Server is reachable

What you're thinking: "Great! The server is reachable. Now let me test if the web server is running on that server."

STEP 6: Test Web Server on That IP

The Command:

curl -I http://192.168.1.100/

Output:

HTTP/1.1 200 OK Content-Type: text/html Server: nginx Content-Length: 5678
✅ Web server responding
✅ HTTP 200 OK
✅ Serving content

What you're thinking: "Perfect! Now let me test the actual domain name to make sure everything works end-to-end."

STEP 7: Test via Domain Name

The Command:

curl -I https://mysite.com/

Output:

HTTP/2 200 date: Wed, 02 Sep 2026 10:45:00 GMT content-type: text/html; charset=utf-8 server: nginx ssl-session-cache: shared:SSL:10m
✅ Domain resolves
✅ Web server responds
✅ HTTPS works
WEBSITE IS ONLINE!

What you're thinking: "Excellent! DNS is working, the server is reachable, and the website is loading. The fix is complete. Let me do a final verification in a browser."

STEP 8: Final Browser Test

Open browser and visit:

https://mysite.com

Verify:

  • 🟢 Page loads immediately
  • 🟢 No "Cannot resolve" errors
  • 🟢 HTTPS secure (green lock)
  • 🟢 Content displays normally
✅ Website loads in browser
✅ Users can access from anywhere
✅ DNS fully working!

✅ Complete Diagnostic Checklist

When DNS isn't resolving, follow this checklist:

  1. ☐ Test locally: nslookup mysite.com
  2. ☐ Check DNS provider: A record exists?
  3. ☐ Verify record value: Correct IP address?
  4. ☐ Create/update A record if missing
  5. ☐ Wait 5-10 minutes for propagation
  6. ☐ Test again: dig mysite.com @8.8.8.8
  7. ☐ Ping IP address: Server reachable?
  8. ☐ Test web server: curl http://IP
  9. ☐ Test domain: curl https://mysite.com
  10. ☐ Browser test: Visit website in browser

Total time: ~15-30 minutes (including propagation wait)
