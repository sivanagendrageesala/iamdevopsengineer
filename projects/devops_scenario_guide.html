🔴 Website Down: Complete Troubleshooting Guide

📞 The Call: "Your website is not loading!" You have 10 minutes to diagnose and fix it.

⏱️ Your Time: SSH → Diagnose → Fix → Verify (3-5 minutes)
WORKFLOW DIAGRAM:

🚀 Step-by-Step Walkthrough

STEP 1: Connect to Server

Open PuTTY and SSH into your server:

Server: 192.168.1.100 Login: myuser Password: ****

You see:

myuser@webserver:~$

What this means: You're logged in, in your home directory (~).

STEP 2: Confirm Your Location

Command:

pwd

Expected Output:

/home/myuser

What you're thinking: "Good, I'm in my home directory. Now let me check if the web server is running."

STEP 3: Check if nginx Is Running

Command:

systemctl status nginx

Output:

● nginx.service - A high performance web server and a reverse proxy server Loaded: loaded (/etc/systemd/system/multi-user.target.wants/nginx.service; enabled; vendor preset: enabled) Active: failed (Result: exit-code) since Wed 2026-08-27 15:30:45 UTC; 5min ago Process: 1234 ExecStart=/usr/sbin/nginx -g daemon on; master_process on; (code=exited, status=1/0) Main PID: 1234 (code=exited, status=1/0) Aug 27 15:30:45 webserver nginx[1234]: nginx: [emerg] bind() to 0.0.0.0:80 failed (48: Address already in use)
⚠️ CRITICAL INFORMATION:

• Active: failed = nginx is DOWN ❌
• bind() to 0.0.0.0:80 failed = Port 80 is already in use
• Address already in use = Another process is using port 80

What you're thinking: "Port 80 is taken by something else. I need to find what's using it."

STEP 4: Find What's Using Port 80

Command (requires sudo):

sudo netstat -tuln | grep 80

Output:

tcp 0 0 0.0.0.0:80 0.0.0.0:* LISTEN 5678/apache2 tcp6 0 0 [::]:80 [::]:* LISTEN 5678/apache2
⚠️ CRITICAL INFORMATION:

• apache2 is using port 80
• Process ID: 5678
• Port 80 is LISTEN-ing (actively in use)
• PROBLEM: This server should run nginx, not apache!
STEP 5: Check nginx Error Log for More Details

Command (read-only, no sudo needed):

tail -20 /var/log/nginx/error.log

Output:

2026-08-27 15:30:45 [emerg] 1234#1234: bind() to 0.0.0.0:80 failed (48: Address already in use) 2026-08-27 15:30:45 [emerg] 1234#1234: bind() to 0.0.0.0:80 failed (48: Address already in use) 2026-08-27 15:30:45 [emerg] 1234#1234: bind() to [::]:80 failed (48: Address already in use) 2026-08-27 15:30:45 [emerg] 1234#1234: still could not bind() 2026-08-27 15:30:45 [alert] 1234#1234: master process exited with code 1
⚠️ WHAT HAPPENED:

• nginx tried to start
• Couldn't bind to port 80 (already in use)
• Tried multiple times
• Finally gave up and exited
STEP 6: Check If Apache Is Supposed To Be Running

Command:

systemctl status apache2

Output:

● apache2.service - The Apache HTTP Server Loaded: loaded (/etc/systemd/system/multi-user.target.wants/apache2.service; enabled; vendor preset: enabled) Active: active (running) since Wed 2026-08-27 14:00:15 UTC; 1h 30min ago Main PID: 5678
⚠️ PROBLEM CONFIRMED:

• Apache is running
• It's been running for 1.5 hours
• It's set to auto-start (enabled)
• This is WRONG for a nginx server!

Decision: Stop apache, disable it, start nginx, verify website works.

STEP 7: Stop Apache

Command (requires sudo):

sudo systemctl stop apache2

Output:

(no output = success!)
✅ Apache is now stopped. Port 80 is free!
STEP 8: Disable Apache Auto-Start

Command (requires sudo):

sudo systemctl disable apache2

Output:

Synchronizing state of apache2.service with SysV service script with /lib/systemd/enable/apache2... Executing: /lib/systemd/update-rc.d apache2 disable Removed /etc/systemd/system/multi-user.target.wants/apache2.service.
✅ Apache will NOT restart on reboot
STEP 9: Start nginx

Command (requires sudo):

sudo systemctl start nginx

Output:

(no output = success!)
✅ nginx is starting...
STEP 10: Verify nginx Is Running

Command:

systemctl status nginx

Output:

● nginx.service - A high performance web server and a reverse proxy server Loaded: loaded (/etc/systemd/system/multi-user.target.wants/nginx.service; enabled; vendor preset: enabled) Active: active (running) since Wed 2026-08-27 15:35:10 UTC; 2s ago Process: 8901 ExecStart=/usr/sbin/nginx -g daemon on; master_process on; (code=exited, status=0/0) Main PID: 8902
✅ CRITICAL INFORMATION:

• Active: active (running) = nginx is UP ✅
• 2s ago = Just started
• No errors in output!
STEP 11: Test The Website

Command:

curl http://localhost:80/

Output:

Hello World!

Website is online!

✅ WEBSITE IS RESPONDING!

• HTTP 200 = Success
• HTML content is loading
• Website works!
STEP 12: Final Verification - Port 80 Status

Command:

sudo netstat -tuln | grep 80

Output:

tcp 0 0 0.0.0.0:80 0.0.0.0:* LISTEN 8902/nginx tcp6 0 0 [::]:80 [::]:* LISTEN 8902/nginx

⚠️ Troubleshooting: What If...?

What if you don't have sudo access?

You CAN do (read-only):

  • pwd - Check location
  • ls -la - List files
  • cd - Navigate
  • systemctl status nginx - Check status
  • tail -f /var/log/nginx/error.log - Watch logs
  • grep "error" /var/log/nginx/error.log - Search logs
  • netstat -tuln | grep 80 - Check ports
  • curl http://localhost:80/ - Test website

You CANNOT do (require sudo):

  • systemctl stop apache2 - Stop service
  • systemctl start nginx - Start service
  • systemctl disable apache2 - Disable service

Solution: Gather all diagnostic info, then call your admin: "Apache is on port 80, nginx can't start. Can you stop apache and start nginx?"

What if netstat command gives "command not found"?

Use alternative:

sudo ss -tuln | grep 80

ss (socket statistics) is the newer command, does the same thing.

What if curl gives "Connection refused"?

Possible reasons:

  • nginx didn't actually start (check systemctl status nginx)
  • nginx is listening on wrong port
  • Configuration error (check tail /var/log/nginx/error.log)
