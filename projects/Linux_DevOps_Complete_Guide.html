1. Linux Basics

pwd - Print Working Directory ▼

Purpose: Displays the full path of the current directory you're working in.

$ pwd
/home/user/documents
Why use it: Useful when navigating through directories to know your current location. Especially helpful when working in terminal sessions where you might lose track of your position.

Real-Time Example

When you open a terminal, you start in your home directory. Use pwd to confirm:

$ pwd /home/john
ls - List Directory Contents ▼

Purpose: Lists files and directories in a location with various formatting options.

ls # List files in current directory ls -l # Long format with permissions, owner, size, date ls -a # Show all files including hidden files ls -lh # Long format with human-readable sizes ls -R # Recursive listing of all subdirectories ls -t # Sort by modification time ls -S # Sort by file size

Real-Time Example

$ ls -lh total 152K -rw-r--r-- 1 john users 1.2K Jan 15 10:30 file1.txt -rw-r--r-- 1 john users 2.5K Jan 14 09:15 file2.txt drwxr-xr-x 2 john users 4.0K Jan 15 11:20 documents
Explanation: The `-l` flag shows detailed information:
  • First column: Permissions (rwxr-xr-x)
  • Second: Link count
  • Third: Owner (john)
  • Fourth: Group (users)
  • Fifth: File size
  • Last columns: Date and filename
cd - Change Directory ▼

Purpose: Changes your current working directory.

cd /home/user # Change to absolute path cd ../ # Go up one directory cd ~ # Go to home directory cd - # Go to previous directory

Real-Time Example - Navigation Scenario

$ pwd /home/john/documents $ cd .. $ pwd /home/john $ cd projects/webapp $ pwd /home/john/projects/webapp $ cd - $ pwd /home/john
💡 Pro Tip: The tilde (~) is a shortcut for your home directory. Use cd - to toggle between two directories quickly.
mkdir - Make Directory ▼

Purpose: Creates new directories.

mkdir mydir # Create a single directory mkdir -p /path/to/deep/dir # Create nested directories mkdir dir1 dir2 dir3 # Create multiple directories

Real-Time Example - DevOps Project Setup

$ mkdir -p /opt/myapp/{src,config,logs,scripts} $ ls -R /opt/myapp /opt/myapp: config logs scripts src
The -p flag creates parent directories automatically. Without it, the command fails if parent directories don't exist.
cp - Copy Files or Directories ▼

Purpose: Copies files or directories.

cp file1.txt file2.txt # Copy a file cp -r dir1 dir2 # Copy directory recursively cp file.txt /home/user/ # Copy to another location cp -v file1.txt file2.txt # Verbose mode cp -i file1.txt file2.txt # Interactive (asks before overwriting)

Real-Time Example - DevOps Config Backup

$ cp -v /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak '/etc/nginx/nginx.conf' -> '/etc/nginx/nginx.conf.bak' $ cp -r /var/www/myapp /var/www/myapp_backup $ ls -l /var/www/ drwxr-xr-x 5 root root 4096 Jan 15 myapp drwxr-xr-x 5 root root 4096 Jan 15 myapp_backup
mv - Move or Rename Files ▼

Purpose: Moves or renames files and directories.

mv oldname.txt newname.txt # Rename a file mv file.txt /home/user/ # Move file to another location mv -i file.txt newlocation/ # Interactive mode

Real-Time Example

$ mv app.py old_app.py $ mv old_app.py /backup/ $ ls /backup/ old_app.py
rm - Remove Files ▼

Purpose: Deletes files or directories.

rm file.txt # Delete a file rm -r directory/ # Delete directory and contents rm -f file.txt # Force deletion without confirmation rm -i file.txt # Interactive (ask before deleting) rm *.log # Delete all matching pattern

Real-Time Example - Cleanup Old Logs

$ ls *.log app-2024-01-10.log app-2024-01-11.log app-2024-01-12.log $ rm -i *.log remove 'app-2024-01-10.log'? y remove 'app-2024-01-11.log'? y remove 'app-2024-01-12.log'? n
⚠️ WARNING: Deletion is permanent! There's no trash can in Linux. Use -i for interactive mode to prevent accidents.
cat & less - View File Contents ▼

Purpose: Displays file contents on screen.

cat file.txt # Display entire file cat file1.txt file2.txt # Display multiple files cat file.txt | less # Display with pagination less largefile.txt # View file with scrolling # In less: press 'q' to quit, 'space' for next page, 'b' for previous

Real-Time Example - Reading Configuration Files

$ cat /etc/hostname myserver $ cat /etc/os-release NAME="Ubuntu" VERSION="20.04 LTS" ID=ubuntu $ less /var/log/syslog # Shows log file page by page - great for large files
When to use each:
  • cat: Small files, combining files, in scripts
  • less: Large files, need to scroll and search
head & tail - View Specific Parts of Files ▼

Purpose: View beginning or end of files, useful for logs.

head file.txt # Show first 10 lines head -n 20 file.txt # Show first 20 lines tail file.txt # Show last 10 lines tail -f logfile.log # Follow log file in real-time tail -F logfile.log # Follow with file reopening (handles rotation)

Real-Time Example - Monitoring Application Logs

$ tail -f /var/log/app.log 2024-01-15 10:25:30 INFO Server started 2024-01-15 10:25:31 INFO Connected to database 2024-01-15 10:25:32 ERROR Connection timeout # Command continues running, showing new lines as they appear # Press Ctrl+C to exit
Pro DevOps Tip: Use tail -f to monitor application logs in real-time while debugging issues.

2. File and Directory Management

find - Search for Files ▼

Purpose: Powerful file search with various criteria.

find /path -name "*.log" # Find files matching pattern find . -type f -name "*.txt" # Find files (not directories) find . -type d -name "test" # Find directories find . -size +100M # Find files larger than 100MB find . -mtime -7 # Find files modified in last 7 days find . -name "*.log" -delete # Find and delete matching files find . -name "*.log" -exec rm {} \; # Find and execute command

Real-Time DevOps Example - Cleanup Old Backups

$ find /backup -name "*.tar.gz" -mtime +30 /backup/app-backup-2023-12-10.tar.gz /backup/app-backup-2023-12-05.tar.gz $ find /backup -name "*.tar.gz" -mtime +30 -delete # Deletes all backups older than 30 days
grep - Search within Files ▼

Purpose: Search for text patterns within files.

grep "pattern" file.txt # Search for pattern grep -r "pattern" /path # Search recursively grep -i "pattern" file.txt # Case-insensitive search grep -v "pattern" file.txt # Show non-matching lines grep -n "pattern" file.txt # Show line numbers grep -c "pattern" file.txt # Count matching lines

Real-Time Example - Debug Application Errors

$ grep -n "ERROR" /var/log/app.log 125: 2024-01-15 10:25:32 ERROR Connection timeout 143: 2024-01-15 10:26:15 ERROR Database query failed 211: 2024-01-15 10:27:45 ERROR Authentication failed $ grep -c "ERROR" /var/log/app.log 3 $ grep -i "warning\|error" /var/log/app.log | head -5
💡 DevOps Use Case: Quickly identify errors in application logs, configuration issues, and parse log files for monitoring and alerting.
sed - Stream Editor (Text Replacement) ▼

Purpose: Stream editor for text manipulation and replacement.

sed 's/old/new/' file.txt # Replace first occurrence per line sed 's/old/new/g' file.txt # Replace all occurrences sed -i 's/old/new/g' file.txt # In-place replacement sed '10d' file.txt # Delete line 10 sed '1,5d' file.txt # Delete lines 1 to 5 sed -n '5,10p' file.txt # Print lines 5 to 10

Real-Time Example - Update Configuration Files

$ cat config.conf database_host=localhost database_port=5432 database_user=admin $ sed -i 's/localhost/192.168.1.100/g' config.conf $ cat config.conf database_host=192.168.1.100 database_port=5432 database_user=admin
DevOps Application: Modify configuration files during deployment, change IP addresses, and update service endpoints in scripts.
awk - Advanced Text Processing ▼

Purpose: Powerful text processing language for parsing and transforming data.

awk '{print $1}' file.txt # Print first column awk '{print $1, $3}' file.txt # Print columns 1 and 3 awk -F: '{print $1}' /etc/passwd # Use colon as delimiter awk '{sum += $1} END {print sum}' file.txt # Sum first column awk '$2 > 100' file.txt # Print rows where column 2 > 100

Real-Time Example - Parse System Files

$ cat /etc/passwd | head -3 root:x:0:0:root:/root:/bin/bash daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin bin:x:2:2:bin:/bin:/usr/sbin/nologin $ awk -F: '{print "User: " $1 " UID: " $3}' /etc/passwd | head -3 User: root UID: 0 User: daemon UID: 1 User: bin UID: 2 $ awk -F: '{sum += $3} END {print "Total UIDs: " sum}' /etc/passwd Total UIDs: 7894

3. User and Permissions Management

User Management (useradd, usermod, passwd) ▼

Purpose: Create, modify, and manage user accounts.

useradd -m username # Create user with home directory useradd -s /bin/bash username # Create with specific shell useradd -G sudo username # Add to group usermod -aG sudo username # Add to sudo group usermod -s /bin/bash username # Change login shell passwd username # Change user password

Real-Time Example - Create Application User

$ sudo useradd -m -s /bin/bash -d /home/appuser appuser $ sudo usermod -aG docker appuser $ id appuser uid=1001(appuser) gid=1001(appuser) groups=1001(appuser),999(docker) $ sudo passwd appuser New password: **** Retype password: **** passwd: password updated successfully
Breaking it down:
  • -m creates home directory
  • -s specifies shell
  • -d sets home directory path
  • -G adds to groups
chmod - Change File Permissions ▼

Purpose: Change file and directory access permissions.

chmod 755 file.sh # rwxr-xr-x (executable script) chmod 644 file.txt # rw-r--r-- (readable file) chmod 600 file.txt # rw------- (private file) chmod +x script.sh # Add execute permission chmod -x script.sh # Remove execute permission chmod -R 755 directory # Recursive change

Permission Numbers Explained

4 = read (r) 2 = write (w) 1 = execute (x) 755 = 7 (owner: rwx) 5 (group: r-x) 5 (others: r-x) 644 = 6 (owner: rw-) 4 (group: r--) 4 (others: r--) 600 = 6 (owner: rw-) 0 (group: ---) 0 (others: ---)

Real-Time Example - Secure Sensitive Files

$ ls -l config.txt -rw-r--r-- 1 root root 245 Jan 15 config.txt $ chmod 600 config.txt $ ls -l config.txt -rw------- 1 root root 245 Jan 15 config.txt $ chmod 755 /opt/scripts/deploy.sh $ ls -l /opt/scripts/deploy.sh -rwxr-xr-x 1 root root 1245 Jan 15 deploy.sh
chown - Change File Owner ▼

Purpose: Change file and directory ownership.

chown username file.txt # Change owner chown username:groupname file.txt # Change owner and group chown -R username directory # Recursive change chown :groupname file.txt # Change group only

Real-Time Example - Setup Application Ownership

$ sudo chown -R appuser:appgroup /opt/myapp $ ls -l /opt/myapp/ total 45 -rw-r--r-- 1 appuser appgroup 2048 Jan 15 app.py -rw-r--r-- 1 appuser appgroup 1024 Jan 15 config.json $ sudo chown root:root /etc/app/config.conf $ ls -l /etc/app/config.conf -rw-r--r-- 1 root root 512 Jan 15 config.conf
sudo - Execute with Elevated Privileges ▼

Purpose: Run commands with root or other user privileges.

sudo command # Execute as root sudo -u username command # Execute as specific user sudo -i # Start interactive root shell sudo !! # Re-run last command with sudo sudo -l # List sudo privileges

Real-Time Example - System Administration Tasks

$ sudo systemctl restart nginx [sudo] password for john: $ sudo -u postgres psql psql (12.10) $ sudo !! [Re-runs the last command with sudo] $ sudo -l User john may run the following commands on this host: (ALL) ALL (ALL) NOPASSWD: /usr/bin/systemctl
⚠️ Use sudo carefully! Misuse can compromise system security. Only grant necessary privileges to users.

4. Process and System Management

ps - List Running Processes ▼

Purpose: Display information about running processes.

ps # Show current user processes ps aux # Show all processes with details ps -ef # Show all processes (different format) ps aux | grep python # Find specific process ps -p 1234 # Show specific PID ps --forest # Show process tree

Real-Time Example - Find Running Services

$ ps aux | grep nginx root 1234 0.0 0.1 125432 5432 ? Ss 10:15 0:00 nginx: master www-data 1235 0.0 0.2 125664 8192 ? S 10:15 0:00 nginx: worker USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND root 1234 0.0 0.1 125432 5432 ? Ss 10:15 0:00 nginx: master
Output columns:
  • PID: Process ID
  • %CPU: CPU usage percentage
  • %MEM: Memory usage percentage
  • VSZ: Virtual memory size
  • RSS: Resident set size (actual memory)
top & htop - Real-Time Process Monitoring ▼

Purpose: Interactive real-time monitoring of system processes.

top # Show live process monitoring top -p 1234 # Monitor specific PID top -u username # Show processes of specific user htop # Enhanced version (more user-friendly) top -b -n 1 # Batch mode (single output)

Real-Time Example - Monitor System Resources

$ top top - 10:30:45 up 5 days, 2:15, 1 user, load average: 0.25, 0.30, 0.35 Tasks: 120 total, 1 running, 119 sleeping %Cpu(s): 5.2 us, 2.1 sy, 0.0 ni, 92.7 id, 0.0 wa PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND 1234 root 20 0 125M 45M 12M S 2.5 2.3 0:15 nginx 2345 user 20 0 85M 32M 8M S 1.2 1.6 0:08 python3
In top, press: M = sort by memory, P = sort by CPU, q = quit, k = kill process
kill - Terminate Processes ▼

Purpose: Send signals to processes to control their execution.

kill 1234 # Send SIGTERM (graceful termination) kill -9 1234 # Send SIGKILL (force kill) kill -15 1234 # Send SIGTERM (default) killall process_name # Kill all processes with name pkill -f "python script.py" # Kill matching process pattern

Real-Time Example - Manage Stuck Processes

$ ps aux | grep stuck_app user 5432 0.0 0.1 125432 5432 ? S 10:15 0:00 stuck_app $ kill 5432 # Process terminates gracefully $ ps aux | grep stuck_app # No output - process has ended # For stubborn processes that don't respond: $ kill -9 5432
⚠️ Use SIGTERM (kill PID) first to allow graceful shutdown. Only use SIGKILL (-9) if necessary, as it doesn't allow cleanup.
systemctl - Manage System Services ▼

Purpose: Control systemd services and check their status.

systemctl start service # Start a service systemctl stop service # Stop a service systemctl restart service # Restart a service systemctl reload service # Reload without restarting systemctl status service # Show service status systemctl enable service # Enable service at boot systemctl disable service # Disable service at boot systemctl list-units --type=service # List all services

Real-Time Example - Manage Web Server

$ sudo systemctl start nginx $ sudo systemctl status nginx ● nginx.service - A high performance web server Loaded: loaded (/etc/systemd/system/nginx.service; enabled) Active: active (running) since Mon 2024-01-15 10:25:30 UTC Process: 1234 ExecStart=/usr/sbin/nginx $ sudo systemctl enable nginx Created symlink /etc/systemd/system/multi-user.target.wants/nginx.service $ sudo systemctl restart nginx

ping - Test Network Connectivity ▼

Purpose: Test connectivity to remote hosts.

netstat / ss - Network Statistics ▼

curl - Data Transfer Tool ▼

Purpose: Transfer data using URLs (HTTP, HTTPS, FTP, etc.).

curl https://example.com # Fetch webpage curl -o output.html https://example.com # Save output curl -H "Header: value" https://example.com # Add headers curl -X POST -d "data=value" https://example.com # POST request curl -u username:password https://example.com # Basic auth curl -I https://example.com # Headers only

10. SSH and Remote Access

ssh - Secure Shell ▼

Purpose: Secure remote access to servers.

ssh user@host # Connect to remote host ssh -i key.pem user@host # Connect with private key ssh -p 2222 user@host # Connect to different port ssh user@host "command" # Execute command remotely ssh -L 8080:localhost:80 user@host # Local port forwarding ssh -R 8080:localhost:80 user@host # Remote port forwarding

Real-Time Example - Remote Server Management

$ ssh user@192.168.1.100 user@server:~$ pwd /home/user $ ssh user@server "systemctl restart nginx" $ ssh user@server "curl localhost" ...
ssh-keygen & ssh-copy-id - SSH Keys ▼

Purpose: Generate and manage SSH key pairs for password-less authentication.

ssh-keygen -t ed25519 # Generate modern key pair ssh-keygen -t rsa -b 4096 # Generate RSA key (compatible) ssh-copy-id -i ~/.ssh/id_rsa.pub user@host # Copy public key ssh-copy-id user@host # Use default key

Real-Time Example - Setup Password-less SSH

$ ssh-keygen -t ed25519 -f ~/.ssh/id_server Generating public/private ed25519 key pair. Enter passphrase (empty for no passphrase): [press Enter] Your identification has been saved in ~/.ssh/id_server Your public key has been saved in ~/.ssh/id_server.pub $ ssh-copy-id -i ~/.ssh/id_server.pub user@server /usr/bin/ssh-copy-id: INFO: Source of key(s) to be installed: "~/.ssh/id_server.pub" /usr/bin/ssh-copy-id: INFO: attempting to log in with the new key(s) Number of key(s) added: 1 $ ssh -i ~/.ssh/id_server user@server # Now logs in without password prompt
scp & sftp - Secure File Transfer ▼

Purpose: Securely copy files between local and remote systems.

scp file.txt user@host:/path/ # Copy to remote scp user@host:/path/file.txt . # Copy from remote scp -r folder user@host:/path/ # Copy folder recursively scp -P 2222 file.txt user@host:/path/ # Different port

13. Tips, Tricks & Best Practices

DevOps Engineer Tips

🔄 Automate Everything

Don't repeat manual tasks. Write scripts and use tools like Ansible, Terraform, or Jenkins to automate deployments and configurations.

🔐 Master SSH and Bash

These are your primary tools. Invest time learning advanced features like key management, port forwarding, and bash scripting.

📋 Understand Permissions

Linux permissions are fundamental. Misconfigurations can cause security issues or prevent services from running.

📊 Monitor Logs Actively

Most issues leave traces in logs. Learn to read logs effectively using grep, tail, and journalctl to debug problems quickly.

📝 Use Version Control

Track all configuration changes in Git. This enables rollbacks and provides an audit trail of changes.

🧪 Test in Staging First

Always test configuration and deployment changes in a staging environment before deploying to production.

📚 Document Runbooks

Create procedures for common tasks and troubleshooting steps. Document how to handle emergencies and failures.

🚨 Set Up Monitoring

Don't rely on manual monitoring. Use tools like Prometheus, Grafana, and Alertmanager for automatic alerting.

💾 Plan for Disasters

Implement regular backups and disaster recovery plans. Test restore procedures regularly to ensure they work.

🔄 Stay Current

Keep systems updated with security patches. Stay informed about new tools, techniques, and best practices in DevOps.
