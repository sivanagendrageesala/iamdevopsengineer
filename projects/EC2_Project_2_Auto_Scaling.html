🚀 EC2 Project 2: Auto-Scaling Web Application

AWS EC2 Advanced → Load Balancing & Auto-Scaling

Project Overview

In this project, you'll build a scalable web application that automatically adjusts capacity based on demand using AWS Load Balancer and Auto Scaling Groups.

Duration: 60-90 minutes | Difficulty: Intermediate | Cost: ~$1-2 per day

What You'll Learn:

  • Create Launch Templates for consistent instance configuration
  • Setup Application Load Balancer (ALB)
  • Create Auto Scaling Groups with scaling policies
  • Monitor scaling activities via CloudWatch
  • Test scaling by generating load

Architecture Overview

Users (Internet) ↓ Application Load Balancer ↓ Target Group (ASG) ├─ EC2 Instance 1 ├─ EC2 Instance 2 └─ EC2 Instance 3 (scales up/down based on CPU load)

How it works: The ALB distributes incoming traffic across multiple EC2 instances. The Auto Scaling Group monitors CPU utilization and adds/removes instances automatically.

Prerequisites

  • Completed EC2 Project 1 (understand basic EC2 concepts)
  • AWS Account with free tier access
  • Understanding of security groups and key pairs

Step 1: Create a Launch Template

1

Navigate to Launch Templates

AWS Console → EC2 → Launch Templates → Create launch template

2

Configure Template

Setting Value
Template name WebServerTemplate
Template version description Web server with Nginx
AMI Amazon Linux 2
Instance type t2.micro or t2.small
Key pair MyEC2KeyPair (from Project 1)
3

Configure Security Groups

Create a new security group named "ASG-WebServer-SG"

Type Port Source
HTTP 80 0.0.0.0/0 (from internet)
HTTPS 443 0.0.0.0/0
SSH 22 Your IP (for debugging)
4

Add User Data Script

This script runs automatically when instances launch

Expand "Advanced Details" → Scroll to "User Data" and enter:

#!/bin/bash
yum update -y
yum install -y nginx

# Create a custom page showing instance details
INSTANCE_ID=$(ec2-metadata --instance-id | cut -d " " -f 2)
AVAILABILITY_ZONE=$(ec2-metadata --availability-zone | cut -d " " -f 2)
PRIVATE_IP=$(ec2-metadata --local-ipv4 | cut -d " " -f 2)

cat > /usr/share/nginx/html/index.html << EOF
<!DOCTYPE html>
<html>
<head>
    <title>Auto-Scaling Demo</title>
    <style>
        body { font-family: Arial; margin: 50px; background: #f0f0f0; }
        .container { background: white; padding: 30px; border-radius: 8px; }
        h1 { color: #ff9900; }
        .info { background: #d1ecf1; padding: 15px; border-radius: 5px; margin: 10px 0; }
    </style>
</head>
<body>
    <div class="container">
        <h1>🎉 Running on Auto-Scaled Instance</h1>
        <div class="info">
            <p><strong>Instance ID:</strong> $INSTANCE_ID</p>
            <p><strong>Availability Zone:</strong> $AVAILABILITY_ZONE</p>
            <p><strong>Private IP:</strong> $PRIVATE_IP</p>
            <p><strong>Timestamp:</strong> $(date)</p>
        </div>
        <p>Refresh the page. If you see different Instance IDs, the load balancer is distributing traffic! 🔄</p>
    </div>
</body>
</html>
EOF

systemctl start nginx
systemctl enable nginx
5

Review and Create

Click Create launch template

✅ Launch template created successfully!

Step 2: Create Application Load Balancer

1

Navigate to Load Balancers

EC2 Dashboard → Load Balancing → Load Balancers → Create load balancer

2

Choose Load Balancer Type

Select Application Load Balancer (ALB) - best for HTTP/HTTPS traffic

3

Configure Load Balancer

Setting Value
Name WebAppLoadBalancer
Scheme Internet-facing
IP address type IPv4
4

Select Availability Zones

  • Default VPC
  • Check at least 2 subnets (different AZs) for high availability

Why? If one AZ goes down, your ALB still operates.

5

Create Security Group for ALB

Create new security group "ALB-SG" with:

Type Port Source
HTTP 80 0.0.0.0/0
HTTPS 443 0.0.0.0/0
6

Configure Routing - Create Target Group

Setting Value
Name WebServers
Protocol HTTP
Port 80
VPC Default
7

Configure Health Checks

The ALB checks instance health regularly

Setting Value
Protocol HTTP
Path /
Port 80
Healthy threshold 2 (consecutive healthy checks)
Unhealthy threshold 2 (remove if 2 failed checks)
Timeout 5 seconds
Interval 30 seconds
8

Review and Create

Review settings and click Create load balancer

✅ Load balancer is being created. This takes 2-3 minutes.
9

Note the Load Balancer DNS Name

Once created, copy the DNS name (e.g., WebAppLoadBalancer-123456.us-east-1.elb.amazonaws.com)

You'll use this to access your application.

Step 3: Create Auto Scaling Group

1

Navigate to Auto Scaling Groups

EC2 Dashboard → Auto Scaling → Auto Scaling Groups → Create Auto Scaling group

2

Select Launch Template

  • Name: WebAppASG
  • Launch template: WebServerTemplate
  • Version: Latest
3

Configure Network Settings

  • VPC: Default
  • Availability Zones: Select at least 2 (e.g., us-east-1a, us-east-1b)

Why 2 AZs? High availability - if one zone fails, instances continue in another.

4

Attach to Load Balancer

  • Check Attach to an existing load balancer
  • Target group: Select "WebServers" (created in Step 2)
5

Enable Health Checks

Setting Value
Health check type ELB (uses Load Balancer checks)
Health check grace period 300 seconds
6

Configure Group Size and Scaling

Setting Value Explanation
Desired capacity 2 Start with 2 instances
Minimum capacity 2 Always keep at least 2
Maximum capacity 4 Scale up to max 4
7

Add Scaling Policies

Scroll to "Automatic scaling policies" and select Target tracking scaling

Setting Value
Metric type Average CPU Utilization
Target value 70

What this means: If avg CPU goes above 70%, add instances. If it drops below 70%, remove instances (down to minimum).

8

Add Tags

Key Value Tag New Instances
Name ASG-WebServer ✓
Environment Production ✓
9

Review and Create

Click Create Auto Scaling group

✅ ASG created! Instances will launch in 30-60 seconds.

Step 4: Test Your Setup

1

Wait for Instances to Launch

Go to EC2 → Instances and wait for 2 instances to be "running"

2

Access via Load Balancer

Open browser and go to: http://WebAppLoadBalancer-xxx.us-east-1.elb.amazonaws.com

You should see the custom page showing instance details.

3

Verify Load Distribution

Refresh the page repeatedly (or use F5)

Watch the Instance ID change - the load balancer is distributing requests!

✅ Load balancer is working!
4

Generate Load to Test Scaling

SSH into one of the instances and run:

ssh -i ~/Downloads/MyEC2KeyPair.pem ec2-user@PUBLIC_IP
# Install load test tool
sudo yum install -y apache2-utils

# Generate load on the local Nginx instance
ab -n 10000 -c 100 http://localhost/

Alternative (from your machine):

curl -s http://WebAppLoadBalancer-xxx.elb.amazonaws.com/ | grep "Instance ID"
5

Monitor Scaling Activity

Go to EC2 → Auto Scaling Groups → WebAppASG

Click "Activity" tab to see scaling events

Click "Instances" tab to see current instances

You should see: New instances launching as CPU increases

6

View CloudWatch Metrics

CloudWatch → Dashboards (create custom) or EC2 → Auto Scaling Groups → Monitor

Watch CPU utilization and instance count over time

Step 5: Cleanup

⚠️ Important: Clean up to avoid charges! This setup costs ~$1-2/day.
  1. Delete Auto Scaling Group: EC2 → Auto Scaling Groups → Select WebAppASG → Delete (instances terminate automatically)
  2. Delete Load Balancer: EC2 → Load Balancers → Select WebAppLoadBalancer → Delete
  3. Delete Target Group: EC2 → Target Groups → Select WebServers → Delete
  4. Delete Launch Template: EC2 → Launch Templates → Select WebServerTemplate → Delete
  5. Delete Security Groups: EC2 → Security Groups → Delete ALB-SG and ASG-WebServer-SG

Key Concepts

  • Launch Template: Reusable configuration for instances
  • Application Load Balancer: Distributes incoming traffic across instances
  • Target Group: Instances managed by the load balancer
  • Health Check: ALB verifies instances are healthy
  • Auto Scaling Group: Manages instance count based on policies
  • Scaling Policy: Rules for adding/removing instances
  • Availability Zone: Independent data center - spread instances across AZs

Troubleshooting

Problem Solution
Load Balancer shows "Unhealthy" targets Check security group allows port 80, Nginx is running, health check path is correct
Instances not launching from ASG Check Launch Template is valid, AZs are selected, subnets have available IPs
Not scaling up during load CPU might not be high enough, check metrics in CloudWatch, increase load
Cannot access load balancer DNS Wait 2-3 min for ALB to fully initialize, check security group allows port 80
