🚀 PART 3: Step-by-Step Troubleshooting

STEP 1: Check Application Error Log

The Command:

tail -50 /var/log/app/error.log

Output:

[2026-09-01 14:45:23] ERROR: Database connection failed [2026-09-01 14:45:23] Exception: SQLSTATE[HY000] [2002] Can't connect to MySQL server on '192.168.1.50' (111) [2026-09-01 14:45:24] ERROR: Database connection failed [2026-09-01 14:45:24] Exception: SQLSTATE[HY000] [2002] Can't connect to MySQL server on '192.168.1.50' (111) [2026-09-01 14:45:25] ERROR: Retrying database connection...
What this means:
• "Can't connect to MySQL server on '192.168.1.50'" = Database unreachable
• "(111)" = Error code 111 = Connection refused
• "Retrying database connection..." = App keeps trying but failing

What you're thinking: "Connection is being refused. The database is either down or the port is blocked. Let me check if MySQL service is running."

STEP 2: Check If MySQL Service Is Running

The Command:

systemctl status mysql

Output:

● mysql.service - MySQL Database Server Loaded: loaded (/etc/systemd/system/mysql.service; enabled; vendor preset: enabled) Active: inactive (dead) since Mon 2026-09-01 14:40:15 UTC; 5min ago Process: 2345 ExecStart=/usr/sbin/mysqld (code=exited, status=1/0) Main PID: 2345 (code=exited, status=1/0) Sep 01 14:40:15 dbserver mysqld[2345]: [ERROR] /usr/sbin/mysqld: Table 'mysql.user' doesn't exist
CRITICAL DISCOVERY:

• "Active: inactive (dead)" = MySQL is NOT RUNNING ❌
• Status: exited at 14:40:15
• Error: "Table 'mysql.user' doesn't exist"
MySQL crashed! System table is missing!

What you're thinking: "MySQL crashed because the 'mysql.user' table is missing. This is a critical system table. The database is corrupted. I need to check the MySQL error log for more details."

STEP 3: Check MySQL Error Log

The Command:

tail -100 /var/log/mysql/error.log

Output:

2026-09-01T14:40:12.345678Z 0 [System] /usr/sbin/mysqld: ready for connections. 2026-09-01T14:40:13.456789Z 1 [ERROR] /usr/sbin/mysqld: Table 'mysql.user' doesn't exist 2026-09-01T14:40:13.567890Z 1 [ERROR] /usr/sbin/mysqld: Fatal error: Can't open and lock privilege tables: Table 'mysql.user' doesn't exist 2026-09-01T14:40:13.678901Z 0 [ERROR] /usr/sbin/mysqld: Aborting 2026-09-01T14:40:15.789012Z 0 [System] /usr/sbin/mysqld: Shutdown complete
What this log tells you:
• 14:40:12 = MySQL started
• 14:40:13 = Tried to load user privilege table
• Found: Table 'mysql.user' doesn't exist!
• 14:40:15 = MySQL aborted and shut down

Root Cause: System table is corrupted/missing

What you're thinking: "The mysql.user table is essential for authentication. Without it, MySQL can't start. I need to repair this table. Let me try starting MySQL in safe mode to fix it."

STEP 4: Check for Orphaned MySQL Processes

The Command:

ps aux | grep mysqld | grep -v grep

Output:

mysql 2345 0.0 5.2 1456234 832456 14:40 ? Sl 0:05 /usr/sbin/mysqld
PROBLEM FOUND:

• Old MySQL process (PID 2345) is STILL RUNNING
• It crashed but didn't fully exit
• File is locked by this old process
• New process can't start

Solution: Kill this orphaned process

What you're thinking: "There's a zombie MySQL process still holding file locks. When I try to restart MySQL, the new process can't grab the files. I need to kill this old process first."

STEP 5: Kill the Orphaned Process

The Command:

sudo kill -9 2345

Verify it's gone:

ps aux | grep mysqld | grep -v grep

Output:

(no output = process is gone)
✅ Old process killed
✅ File locks released
✅ Ready to restart MySQL
STEP 6: Start MySQL in Recovery Mode

The Command:

sudo mysqld_safe --skip-grant-tables &

What this does:

  • mysqld_safe = Safe startup script for MySQL
  • --skip-grant-tables = Skip user authentication (bypass corrupted mysql.user table)
  • & = Run in background

Check if it started:

ps aux | grep mysqld | grep -v grep

Output:

mysql 3456 2.5 15.2 2456234 2432456 14:52 ? Sl 0:02 /usr/sbin/mysqld --skip-grant-tables
✅ MySQL started in recovery mode
✅ Can now connect without password
✅ Can repair corrupted tables

What you're thinking: "Good! MySQL started with --skip-grant-tables. This allows me to connect without the mysql.user table. Now I can run mysql_upgrade to fix the corrupted tables."

STEP 7: Repair Corrupted Tables

The Command:

mysql_upgrade --skip-grant-tables

Output:

Checking if update is needed. Repairing mysql.user Repairing mysql.db Repairing mysql.tables_priv Repairing mysql.columns_priv Repairing mysql.host ... Repairing tables. OK
✅ System tables repaired
✅ mysql.user table restored
✅ Permissions fixed

What this does:

  • Checks MySQL system tables for corruption
  • Repairs damaged tables automatically
  • Rebuilds user privilege tables
  • Updates table schemas to current version
STEP 8: Restart MySQL Normally

Kill the safe startup:

sudo pkill mysqld

Wait a moment, then start normally:

sudo systemctl start mysql

Check status:

systemctl status mysql

Output:

● mysql.service - MySQL Database Server Loaded: loaded (/etc/systemd/system/mysql.service; enabled; vendor preset: enabled) Active: active (running) since Mon 2026-09-01 14:55:23 UTC; 2s ago Process: 3789 ExecStart=/usr/sbin/mysqld (code=exited, status=0/0) Main PID: 3790
✅ MySQL is RUNNING!
✅ Service started successfully
✅ Ready to accept connections

What you're thinking: "Perfect! MySQL is running normally now. The corrupted tables are fixed. Let me test the connection to make sure it's working."

STEP 9: Test Database Connection

The Command:

mysql -u root -p -e "SHOW DATABASES;"

Output:

Enter password: +--------------------+ | Database | +--------------------+ | information_schema | | mysql | | performance_schema | | myapp | +--------------------+
✅ Connected successfully!
✅ System databases intact
✅ Application database (myapp) accessible

What you're thinking: "Great! I can connect to MySQL and all databases are visible. Now let me check if the application can connect."

STEP 10: Test Application Connection

The Command:

php /var/www/test_db_connection.php

Output:

Database: myapp Connection Status: OK ✅ Tables: 5 Users: 1234 Orders: 5678
✅ Application connects to database!
✅ Can query data
✅ No connection errors

The Command:

tail -20 /var/log/app/error.log

Output:

[2026-09-01 14:55:45] INFO: Database connection restored [2026-09-01 14:55:45] INFO: Syncing application state [2026-09-01 14:55:46] INFO: Application ready [2026-09-01 14:55:47] INFO: Processing queued requests

✅ Practice Checklist

When you encounter a database connection error:

  1. ☐ Check application error log for specific error
  2. ☐ Check if MySQL service is running (systemctl status mysql)
  3. ☐ Check MySQL error log for startup issues
  4. ☐ Check for orphaned processes (ps aux)
  5. ☐ Kill old processes if needed (kill -9)
  6. ☐ Try starting MySQL in safe mode
  7. ☐ Run mysql_upgrade to repair tables
  8. ☐ Restart MySQL normally
  9. ☐ Test manual connection (mysql -u root -p)
  10. ☐ Test application connection
  11. ☐ Verify website is responding

Total time: ~15 minutes
