📊 What is CloudWatch?

CloudWatch — AWS's monitoring, logging, and observability service. It collects metrics, logs, and events from your AWS resources and helps you understand what's happening in your infrastructure.

Metrics

Track performance data (CPU, memory, disk I/O, network)

Logs

Centralized log collection from applications and services

Alarms

Automated notifications when thresholds are breached

Dashboards

Visualize metrics and logs in custom dashboards

📈 Metrics

Metrics are time-series data points that measure the performance of your resources. AWS automatically provides basic metrics for EC2, RDS, and other services.

Custom Metrics

Beyond AWS-provided metrics, you can push custom metrics from your applications:

  • Application-specific performance data
  • Business metrics (orders, users, revenue)
  • Custom errors or warnings
  • Database query performance
💡 Pro Tip: CloudWatch retains metrics for 15 months. High-resolution metrics (1-second granularity) cost more but provide finer detail.

📝 CloudWatch Logs

Centralized log management for all your applications and AWS services. Logs are organized into Log Groups and Log Streams.

Log Structure

Log Group

Collection of log streams for a specific service or application. Example: /aws/ec2/web-server

Log Stream

Sequence of log events from a single resource. Example: i-1234567890abcdef0

Log Filtering & Searching

CloudWatch Logs Insights allows you to query logs using a powerful query language:

  • fields @timestamp, @message, status — Select specific fields
  • filter status = 500 — Find errors
  • stats count() by service — Aggregate metrics
  • sort @timestamp desc — Order results

🚨 Alarms

CloudWatch Alarms monitor metrics and trigger actions when thresholds are breached. They can send notifications or trigger Auto Scaling actions.

Alarm States

✓ OK — Metric is within normal range
⚠ INSUFFICIENT DATA — Not enough data to evaluate
🚨 ALARM — Metric has breached the threshold

Setting Up an Alarm

1. Choose a Metric

Select the metric you want to monitor (e.g., CPU Utilization)

2. Set Threshold & Conditions

Define when alarm triggers: "If CPU > 80% for 5 consecutive minutes"

3. Configure Actions

What happens when alarm triggers: Send email, text, or trigger Lambda

4. Add Notifications

Use SNS topics to send notifications to email, Slack, PagerDuty, etc.

💡 Best Practice: Test alarms in a non-production environment first. Always set up multiple notification channels for critical alarms.

🔧 Troubleshooting Guide

No Metrics Appearing

Step 1: Verify Resource Type

  • CloudWatch only collects metrics from supported AWS resources
  • EC2 instances start reporting metrics automatically
  • Custom applications need CloudWatch agent or SDK installed

Step 2: Check IAM Permissions

  • For EC2 instances: attach IAM role with CloudWatchAgentServerPolicy
  • For applications: ensure credentials have cloudwatch:PutMetricData permission

Step 3: Verify CloudWatch Agent

  • Check if CloudWatch agent is installed on EC2: systemctl status amazon-cloudwatch-agent
  • Verify agent configuration file: /opt/aws/amazon-cloudwatch-agent/etc/config.json
  • Check agent logs: /opt/aws/amazon-cloudwatch-agent/logs/

Logs Not Appearing

Step 1: Verify Log Group Exists

  • Check CloudWatch Logs console for the log group
  • For Lambda: automatic log group should be created at first invocation
  • For other services: manually create log group if needed

Step 2: Check IAM Permissions

  • Application needs logs:CreateLogStream and logs:PutLogEvents permissions
  • Verify the IAM role/user has these permissions

Step 3: Check Application Logs

  • Application is sending logs to CloudWatch correctly
  • Check application logs on the instance for errors
  • Verify log format is correct for the logging library

Alarm Not Triggering

Checklist:

  • ✓ Alarm state is not "ALARM" yet (threshold not breached)
  • ✓ Alarm is enabled (not disabled)
  • ✓ SNS topic exists and subscriptions are confirmed
  • ✓ Check alarm history in CloudWatch console
  • ✓ Verify threshold and evaluation period settings

High CloudWatch Costs

Cost Reduction Tips:

  • Reduce custom metric frequency (push less often)
  • Use log retention policies (auto-delete old logs)
  • Consolidate log groups and streams
  • Use metric math instead of creating multiple metrics
  • Filter logs before sending to CloudWatch
