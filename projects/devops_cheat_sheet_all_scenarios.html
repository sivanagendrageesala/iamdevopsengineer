🔍 SCENARIO 1: Website Down (Port Conflict)

⚠️ Alert: Website not loading | CPU: Normal | Memory: Normal | Error: Port 80 in use
Quick Fix (5 steps):
  1. Check nginx status: systemctl status nginx
  2. Find what's using port 80: sudo netstat -tuln | grep 80
  3. Stop wrong service: sudo systemctl stop apache2
  4. Disable auto-start: sudo systemctl disable apache2
  5. Start nginx: sudo systemctl start nginx

Key Commands:

systemctl status nginx sudo netstat -tuln | grep 80 ps aux | grep apache sudo systemctl stop apache2 sudo systemctl disable apache2 sudo systemctl start nginx curl http://localhost:80/

What to Look For:

Check Healthy Status Problem Status
nginx status Active: active (running) Active: failed / inactive
Port 80 owner nginx using port 80 apache2 / other service
Website response HTTP 200 OK Connection refused

💾 SCENARIO 2: Disk Full

⚠️ Alert: Disk 95% full | Available: 5GB | Critical space warning
Quick Fix (7 steps):
  1. Check overall disk: df -h
  2. Find large directories: du -sh /* | sort -hr
  3. Check /var/log: du -sh /var/log/*
  4. Check file ages: ls -lh /var/log/
  5. Check if file is in use: lsof | grep syslog
  6. Delete old rotated logs: rm /var/log/syslog.1 /var/log/syslog.2
  7. Verify space freed: df -h

Key Commands:

df -h du -sh /* | sort -hr du -sh /var/* | sort -hr du -sh /var/log/* | sort -hr ls -lh /var/log/syslog* lsof | grep /var/log/syslog rm /var/log/old_file systemctl status nginx

What to Look For:

Check Healthy Problem
Disk Usage % < 80% > 90%
Large directory /var/log < 10GB /var/log > 50GB
Log age Current + 1 backup Multiple old copies

⚡ SCENARIO 3: High CPU/Memory Usage

⚠️ Alert: CPU: 95% | Memory: 92% | Load: 8.45 | Website SLOW
Quick Fix (6 steps):
  1. Check CPU/Memory: top -bn1 | head -20
  2. Find top process: Look at %CPU and %MEM columns
  3. Check MySQL queries: mysql -e "SHOW PROCESSLIST;"
  4. Kill slow query: mysql -e "KILL 1;"
  5. Verify CPU dropped: top -bn1 | head -10
  6. Find root cause: ps aux | grep backup or check cron

Key Commands:

top -bn1 | head -20 ps aux | grep mysql mysql -u root -p -e "SHOW PROCESSLIST;" mysql -u root -p -e "KILL 1;" free -h uptime crontab -l

What to Look For:

Metric Healthy Problem Action
CPU Usage < 20% > 80% Find process using CPU
Memory Usage < 70% > 85% Find memory hog
Query Time < 1 second > 30 seconds Kill slow query
Load Average < 4 (on 4-core) > 8 Too many tasks

🗄️ SCENARIO 4: Database Connection Failed

⚠️ Alert: Cannot connect to database | Error: Connection refused | Website Error 500
Quick Fix (8 steps):
  1. Check service status: systemctl status mysql
  2. Check error log: tail -100 /var/log/mysql/error.log
  3. Find old processes: ps aux | grep mysqld
  4. Kill orphaned process: sudo kill -9 PID
  5. Start safe mode: sudo mysqld_safe --skip-grant-tables &
  6. Repair tables: mysql_upgrade --skip-grant-tables
  7. Restart normal: sudo systemctl start mysql
  8. Test connection: mysql -u root -p -e "SHOW DATABASES;"

Key Commands:

systemctl status mysql tail -100 /var/log/mysql/error.log ps aux | grep mysqld | grep -v grep sudo kill -9 PID sudo mysqld_safe --skip-grant-tables & mysql_upgrade --skip-grant-tables sudo systemctl start mysql mysql -u root -p -e "SHOW DATABASES;"

What to Look For:

Check Healthy Problem
Service Status Active: active (running) Active: inactive / failed
Error Log No [ERROR] messages [ERROR] Table doesn't exist
Processes One mysqld process Multiple/orphaned mysqld
Connection Test mysql -e works Access denied / Connection refused

✅ Universal Troubleshooting Steps

Use these for ANY problem:
  1. Gather Information: Collect error messages, logs, alerts
  2. Check Status: systemctl status, systemctl list-units --failed
  3. Read Error Logs: tail -100 /var/log/[service]/error.log
  4. Check Resources: top, free -h, df -h, netstat
  5. Identify Root Cause: Why did it fail?
  6. Take Action: Fix, restart, repair
  7. Verify Fix: Test manually, check logs
  8. Prevent Recurrence: Optimize, schedule, monitor

💡 Pro Tips

✅ DO:
  • Always check error logs first - they tell the real story
  • Check status before restarting - understand WHY it failed
  • Take notes of what you did and what worked
  • Test after fix - don't assume it's working
  • Monitor - watch for recurrence
⚠️ DON'T:
  • Never kill -9 without checking what you're killing
  • Never delete files you're not 100% sure about
  • Never restart without checking error logs first
  • Never make changes on production without knowing impact
  • Never ignore "could not delete" errors - file might be in use
